# 不吃亏 / Buchikui

> 消费前多看一眼，消费后少走弯路。

**不吃亏**是一个面向普通消费者的公益型行动指南：不做情绪曝光，不替用户“吵架”，重点帮助用户把消费纠纷变成一条可验证、可推进的证据链。

## 当前 Demo

### CASE 001：如何租车维权

首页已经直接落成第一个可用案例，覆盖 6 个高频场景：

1. 预订后无车，但押金 / 预授权仍被冻结或扣留
2. 实际车辆与订单、合同车辆不符
3. “提灯验损”与还车后追加索赔
4. 平台保障与门店保障重复购买
5. 出险后因车辆性质、承保信息等原因出现理赔争议
6. 交通违法与额外“待处理费 / 管理费”争议

页面提供：

- 按问题快速跳转的场景导航
- 每个场景的「立刻做 / 核对什么 / 留什么证据」
- 可勾选、浏览器本地保存的 10 项证据清单
- 商家 / 平台 → 12328 → 12315 → 法院的维权路径
- 公安交管与交通运输主管部门的职责区分
- 一键复制书面沟通模板
- Web Share 分享与打印 / 存 PDF
- 官方依据与免责声明

## 产品原则

- **行动优先**：用户先知道下一步该做什么，再补背景知识
- **证据导向**：订单、合同、实车、车况、定损、扣款必须能串起来
- **渠道准确**：区分平台、行业主管部门、市场监管、公安交管和法院
- **去情绪化**：目标是退款、解除冻结、取消收费或取得凭证，不是“出口气”
- **公开可核验**：法规与官方渠道直接链接到政府 / 法院来源

## 当前技术实现

最小实现保持为单文件静态站：`index.html`。

- 无框架、无构建步骤、无后端
- GitHub Pages 直接部署
- 原生 HTML / CSS / JavaScript
- `localStorage` 保存证据清单状态
- Web Share API + Clipboard fallback
- `window.print()` 支持打印 / 保存 PDF

这是满足当前需求的最简单长期方案；等第二、第三个 case 出现后，再根据真实重复结构抽取共享组件和内容数据层。

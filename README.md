# 不吃亏 / Buchikui

> 消费前多看一眼，消费后少走弯路。

**不吃亏**是一个面向普通消费者的公益型行动指南：不做情绪曝光，不替用户“吵架”，重点帮助用户把消费纠纷变成一条可验证、可推进的证据链。

## 当前 Demo

首页现在是一套 **随机 Case 阅读器**：

- 直接访问首页时，每次加载从现有 Case 中随机展示一份；
- 分享当前 Case 时，链接会自动附带 `?case=...`，确保接收者打开的是同一份内容；
- 页面长度服从问题复杂度：能用 4 个事实讲清，就不堆成 8 个场景；简单问题可以使用 1–2 屏的 `compact` 短页。

### CASE 001：如何租车维权

租车页不再穷举风险，压缩为 **4 个关键事实**：

1. **认主体**：“官方授权”不等于直营网点；看营业执照、合同出租方和实际收款方
2. **认车辆**：订单、合同、车牌、行驶证、保险必须能对应到同一辆车
3. **认扣款权**：“信用免押”不等于平台当然可以按商家主张直接划款；要看具体合同 / 授权、平台审查与申诉流程
4. **认收费依据**：验损、保险、违章管理费等都必须能说明合同条款、事实、金额计算和收费主体

证据清单同步压缩为 6 项，只保留主体、订单合同、车辆、车况、授权/保障和收费依据。

### CASE 002：如何美容美发纠纷维权

覆盖 6 个高频场景：

1. 办卡 / 充值后退费争议
2. 低价引流后临时加价
3. 未经明确同意擅自加项目、换产品或换服务人员
4. 烫染、护理后出现过敏、灼伤、断发或皮肤损伤
5. 搬店、转店、换经营主体、闭店后旧卡无法正常使用
6. 生活美容越界开展医疗美容项目

### CASE 003：如何追讨银行小额账户管理费

这是第一个 `compact` Case，只保留 1–2 屏：

1. 先判断账户是否属于应免收账户，尤其核对 2017 年 8 月 1 日之后的唯一账户收费
2. 拉出小额账户管理费 / 账户管理费 / 年费扣费明细
3. 向银行申请核查并退回不应收取的费用，保留工单号和答复
4. 银行无法合理解释或拒绝处理时，通过 12378 继续投诉

页面能力按 Case 复杂度使用：

- Standard Case：关键事实 / 必要场景、证据清单、维权路径、沟通模板
- Compact Case：判断条件 + 3–4 步行动路径 + 官方依据
- 所有 Case：随机首页、固定分享链接、打印、官方来源与免责声明

## 产品原则

- **关键事实优先**：页面不是百科；只保留会改变用户判断和行动的事实
- **行动优先**：用户先知道下一步该做什么，再补背景知识
- **证据导向**：留下能证明主体、约定、授权、事实与金额的材料，不追求截图数量
- **按问题复杂度设计页面**：简单问题保持短，不为了结构完整制造多余内容
- **渠道准确**：按纠纷性质区分平台、实际经营者、市场监管、行业主管部门、金融监管、卫生健康部门、公安交管和法院
- **去情绪化**：目标是退款、解除合同、取消收费、取得凭证或处理损害，不是“出口气”
- **公开可核验**：法规与官方渠道直接链接到政府 / 监管 / 法院来源

## 当前技术实现

继续保持纯静态站，不引入框架、构建系统或后端：

- `index.html`：统一页面壳
- `styles.css`：共享视觉系统
- `cases.js`：标准 Case 的结构化内容数据
- `compact-cases.js`：短 Case 内容数据
- `app.js`：随机选择、standard/compact 渲染、证据状态、分享、打印、复制模板
- GitHub Pages 直接部署

当前只有两种明确页面形态：`standard` 和 `compact`。不为每个 Case 单独复制页面，也不增加额外路由或框架。

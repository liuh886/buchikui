# 不吃亏 / Buchikui

> 消费前多看一眼，消费后少走弯路。

**不吃亏**是一个面向普通消费者的公益型行动指南：不做情绪曝光，不替用户“吵架”，重点帮助用户把消费纠纷变成一条可验证、可推进的证据链。

## 当前 Demo

首页现在是一套 **随机 Case 阅读器**：

- 直接访问首页时，每次加载从现有 Case 中随机展示一份；
- 分享当前 Case 时，链接会自动附带 `?case=...`，确保接收者打开的是同一份内容；
- 每个 Case 的证据清单使用独立 `localStorage` key，不会互相串状态。

### CASE 001：如何租车维权

覆盖 7 个高频场景：

1. 门头写“滴滴租车官方授权”，但实际签约、收款和履约主体可能是第三方商家；先核对经营主体、合同主体与收款主体
2. 预订后无车，但押金 / 预授权仍被冻结或扣留
3. 实际车辆与订单、合同车辆不符
4. “提灯验损”与还车后追加索赔
5. 平台保障与门店保障重复购买
6. 出险后因车辆性质、承保信息等原因出现理赔争议
7. 交通违法与额外“待处理费 / 管理费”争议

### CASE 002：如何美容美发纠纷维权

覆盖 6 个高频场景：

1. 办卡 / 充值后退费争议
2. 低价引流后临时加价
3. 未经明确同意擅自加项目、换产品或换服务人员
4. 烫染、护理后出现过敏、灼伤、断发或皮肤损伤
5. 搬店、转店、换经营主体、闭店后旧卡无法正常使用
6. 生活美容越界开展医疗美容项目

页面统一提供：

## 产品原则

- **行动优先**：用户先知道下一步该做什么，再补背景知识
- **证据导向**：把经营主体、付款、合同、服务、损害、扣款或余额串成完整事实链
- **渠道准确**：按纠纷性质区分平台、实际经营者、市场监管、行业主管部门、卫生健康部门、公安交管和法院
- **去情绪化**：目标是退款、解除合同、取消收费、取得凭证或处理损害，不是“出口气”
- **公开可核验**：法规与官方渠道直接链接到政府 / 法院来源

## 当前技术实现

继续保持纯静态站，不引入框架、构建系统或后端：

- `index.html`：统一页面壳
- `styles.css`：共享视觉系统
- `cases.js`：所有 Case 的结构化内容数据
- `app.js`：随机选择、渲染、证据状态、分享、打印、复制模板
- GitHub Pages 直接部署

这是当前规模下最简单、可持续的结构：以后增加 Case，只需要在 `cases.js` 中增加一份数据，不复制页面，也不引入额外抽象层。

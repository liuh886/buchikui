# Buchikui CASE Content Standard

> 更新：2026-09-18

## 1. 写作对象

写给正在付款、签字、确认、交付、退款、投诉或准备起诉的普通消费者。

不要从法律体系讲起。先写用户现实中会遇到的话：

- 到店没车怎么办；
- 美容院换老板，卡还能不能退；
- 平台直接扣押金有没有依据；
- 维修第一次没修好，又说别的部件也坏了怎么办。

## 2. 一个 CASE 的最小结构

### 现实问题

标题 + 一段说明。只回答“发生了什么、为什么值得注意”。

### 权威依据

每条材料至少记录：

- `type`：法律 / 行政法规 / 司法解释 / 部门规章 / 监管文件 / 典型案例 / 裁判等；
- `authority`：发布机关或法院；
- `document`：文件名或案号；
- `effective` / 日期：有则写；
- `title`：用消费者能理解的一句话提炼；
- `text`：准确概括原文边界；
- `action`：这条材料对应的现实提醒；
- `sources`：优先官方一手链接。

`legal-updates.js` 是这层的唯一权威数据源，不再另建“新规列表”。

### 现实提醒

每个场景最多两个层次：

- **关键事实**：哪些事实会改变责任、授权、金额或证据；
- **现实提醒**：消费者此时最值得做 / 不做什么。

不再增加“风险”“结论”“原理”“怎么办”“AI 建议”等重复标签。

### 纠纷后的工具

Evidence 和 Route 只在确实必要时出现。它们是末端支持，不是产品主角。

## 3. 裁判纪律

普通裁判只能说明：

> 在这些事实下，这个法院如何认定。

不能写成：

> 法律规定所有类似情况都必须如此。

指导性案例、典型案例、监管处罚案例也必须标明其制度地位。

## 4. 政策和管理规定

“权威依据”不限于判决。新的管理办法、部门规章、监管通知、规范性文件，只要会改变消费者在现实交易中应注意的事项，就应进入对应 CASE。

不要把政策文件做成新闻。必须完成翻译：

**文件要求什么 → 对哪类交易有效 → 消费者因此应该注意什么。**

## 5. 删除规则

以下内容默认删除，而不是继续折叠：

- 仅用于显得完整的章节；
- 与其他模块重复的提醒；
- AI 式总结句、空泛“先确认”“综合判断”；
- 不改变任何现实动作的背景知识；
- 无法追溯到可靠出处的法律结论。

## 6. 语气

短、明确、可核验。允许鲜明提醒，但事实和评价必须分开。

不要写成客服话术、律师函模板或 AI 助手对话。

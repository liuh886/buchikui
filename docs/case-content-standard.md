# 不吃亏 / Buchikui — CASE Content Standard

> 状态：Normative  
> 适用范围：新增 CASE、修改既有 CASE、吸收消费者反馈  
> 目标：**页面尽量简单，但不能漏掉会改变消费者权利位置、证据位置或后续责任判断的关键点。**

## 1. 核心原则

### 1.1 简化表达，不简化争议关键点

可以删背景解释、普通办事流程、重复提醒和百科式知识；不能为了页面更短而删掉未来投诉、调解或诉讼真正会争的事实节点。

统一判断：

> **能删解释，不能删争议关键点；能合并表述，不能让消费者无意识地把关键事实做没。**

### 1.2 什么才算“关键点”

一个信息进入 CASE 核心内容，优先应能对应下面至少一种依据：

1. **法律法规 / 监管规则明确要求或禁止的事项**：例如经营主体、价格、服务内容、授权、告知、交付、退款、收费依据；
2. **公开判决或典型争议中真正影响责任判断的焦点**：例如是否明确同意、是否提前告知、损伤是否既有、平台是否有扣款授权、金额是否有实际依据；
3. **消费者自己的动作会改变后续证据或权利位置**：例如主动取消、签字确认、点击同意、接受换车 / 转卡 / 新协议、确认“无异议”、同意新增项目或结算方案；
4. **关键证据当下不固定以后很难补**：例如旧伤、现场价格、原始合同 / 页面、服务前状态、经营主体、当时版本的授权条款。

普通流程信息不因为“有用”就自动成为关键点。办理顺序、一般提醒、常规时限、操作入口等，如果不改变争议判断，可以放在 Route 或说明里，不占据 CASE 的核心判断位置。

### 1.3 防止“为了省事而让步”

这是“不吃亏”必须特别提醒的一类节点。

编辑每个 CASE 时，都要问：

> **消费者为了赶时间、图方便或尽快结束争议，最容易做出哪个动作，而这个动作以后可能被对方解释为“你同意了 / 你确认了 / 你主动取消了 / 你接受了这个方案”？**

如果存在，就应该在对应场景里直接提醒，并告诉用户怎样保留真实意思表示。

典型形式：

- 商家无法履约时，不要为了退款方便把“商家无车”操作成“用户主动取消”；
- 车辆旧伤没有核对清楚时，不要为了快提车直接确认“车况无异常”；
- 没有同意新增项目或价格时，不要让“已经做了 / 已经结账”替代你的明确同意；
- 原门店搬迁、转让或闭店时，没搞清旧债务由谁承担前，不要为了继续消费直接签转卡或补差协议；
- 对争议扣款、赔偿或结算有异议时，不要让一次快捷确认变成对事实、责任或金额的无条件认可。

这里的目标不是教用户“什么都拒绝”，而是避免真实意思和关键异议因为一个快捷操作消失。

## 2. Standard CASE 的默认结构

保持现有最小闭环：

**一句主张 → 3–4 个立即动作 → 找到我的问题 → 场景 → 关键证据 → 处理路径 → 可复制模板 → 来源 → 最终经验**

不是每个 CASE 都必须增加额外模块。只有确实帮助用户判断时才增加，例如“正常服务基线”。

### Hero

Hero 只做两件事：

1. 用一句主张说清这个 CASE 的核心问题；
2. 用标题下第一段完成问题定性，让第一次进入页面、没有任何背景知识的用户立刻知道：**发生了什么 / 为什么和自己有关 / 本文具体解决什么。**

标题下第一段是**定性段，不是行动段**。默认用 2–4 句，先把读者放进正确语境，再进入 Immediate Actions、判断条件或处理步骤。

- 政策 / 收费类 CASE：优先按 **规则或政策变化 → 现实执行落差 → 本文处理目标** 来写；
- 服务纠纷类 CASE：优先按 **正常应发生什么 → 实际可能在哪一步失灵 → 本文帮助用户定位和处理什么** 来写。

如果某个 CASE 近年出现了**新的法律法规、司法解释、监管整治或高度典型的公开案件**，首段可以优先选其中最有解释力的 1–2 个信号，直接揭示“规则现在怎么变了、现实中最常出什么问题”。推荐结构是：**最新规则 / 权利变化 → 典型现实问题 → 本文处理范围**。这样做的目的不是追新闻，而是让用户马上理解为什么这件事现在值得注意。

不要把首段写成政策时间线或案例堆砌。只有能显著帮助用户理解当前权利位置、典型风险或争议焦点的信息才进入 Hero；完整法条、例外、更多案例和操作步骤继续放到后续层级。

不要一开头就写“先别……”“先查……”“你应该……”，除非前一句已经完成问题定性。第一段只负责让用户马上看懂这是什么问题以及为什么值得继续看。

### Immediate Actions

通常 3–4 项。优先保留会保护消费者后续位置的动作，而不是一般性提醒。

每项尽量写成：

**对象 + 动作 + 要得到 / 保存的结果**

避免“注意留证”“依法维权”“与商家协商”等空泛表达。

## 3. 场景是主要写作单位

每个 Standard CASE 场景默认只保留：

### 关键事实

回答：

> **法律 / 裁判真正会看哪个事实？什么事实会改变责任判断？**

法规、判例和专业解释只服务于这个判断，不写成小论文。

### 现在做什么

回答：

> **为了不丢掉这个关键事实或异议，我现在具体应该做什么？**

默认写成一个简洁段落；但如果几个动作共同构成一个争议关键点，必须按真实顺序保留。

例如取还车验损可以保持为一个场景，但不能丢掉：

**经营者说明已有损伤 → 双方核对车况记录 → 漏标当场提出并补记 → 再独立留影 → 还车用同一基准复核 → 索赔时要求损伤、责任和金额依据。**

真正要保护的是“旧伤是否在交车时被告知和确认”“消费者是否当场提出遗漏”“后来索赔能否证明新增损伤及金额”，而不是单纯教用户拍更多照片。

## 4. 证据与路径

### Evidence

证据不是材料名堆积。优先保留与法律义务、裁判争议焦点直接对应的材料，并说明它解决什么争议。

如果有明显时间顺序，优先按：

**事前 / 当场固定 → 发生争议后补强**

来组织。

### Route

Route 负责告诉用户争议发生后找谁、带什么、要什么结果。

每一步尽量回答：

**什么时候升级 → 找谁 → 带什么 → 要什么结果**

普通办事流程留在 Route；不要把它们误当成“决定输赢的关键点”。

## 5. 法律、判决与关键点必须对应

关键点不能只因为“听起来合理”就进入正文。

新增或重写关键点时，应在 CASE 的 Sources 或研究依据中能够回溯到：

- 当前有效的法律法规、司法解释、监管规则或官方规则；或
- 公开裁判 / 典型案例中已经出现的真实争议焦点。

写法只保留一个原则：

> **法条只写法条明确规定的；判决只写该案实际认定的；我们从这些争议中提炼出的操作提醒，就明确写成操作提醒。三者不要混成同一种确定性。**

个案判决不得直接泛化成所有类似纠纷的必然结论。

如果某个操作提醒没有任何法律义务、裁判争议或明显证据风险支撑，就不应因为“可能有用”而占据核心位置。

## 6. 新信息与消费者反馈怎么进入正文

默认顺序：

1. **先看它是否揭示新的法律 / 裁判争议关键点；**
2. **优先替换弱表达或补进已有关键事实 / 行动；**
3. **只有确实改变责任判断、证据位置或处理路径时，才新增场景或模块。**

消费者反馈是发现现实问题的线索，不是自动成立的事实规则。涉及法律、监管、平台政策、收费、医疗、保险、法院程序等内容，发布前仍需核验当前可靠来源。

不要把每条新经验 append 到正文，避免 CASE 随时间不断膨胀。

## 7. Compact CASE

简单问题继续使用 Compact：

**一句主张 → 判断 / 条件 → 3–4 步处理 → 必要模板 / 说明 → 来源 → 最终经验**

不要为了形式统一强行补齐 Standard CASE 的所有模块。

Compact CASE 同样遵守 Hero 的首段定性规则：标题下第一段先让用户看懂“发生了什么 / 为什么和我有关 / 本文解决什么”，资格判断和操作步骤从下一层开始。

## 8. 最终经验 / Takeaway

每个 CASE 最底部必须有一个 `takeaway`，放在 Sources 和免责声明之后，作为用户离开这一页前看到的最后一句。

它回答的不是“这次纠纷怎么处理”，而是：

> **如果下次重新做选择，最先应该改变什么，才能从源头减少再次吃亏？**

规则保持简单：

- **只写一句；**
- **必须能迁移到下一次消费或决策；**
- **不复述证据清单和维权步骤；**
- 可以有明确的编辑立场，但不能把经验判断伪装成法律结论。

例如：

- 租车：优先选择自营租赁公司，而不是只看平台广告和授权门店；
- 通讯费：面对价格歧视不要沉默；
- 银行收费：国家有规定，但消费者不监督时，规定未必会自动得到执行；
- 美容美发：理性消费者始终避免预付费。

## 9. 发布前只检查这 5 件事

1. 标题下第一段是否让第一次进入页面的用户直接知道**发生了什么、为什么和自己有关、本文解决什么**；如果近期存在显著的新规、监管动作或典型公开问题，是否用最少的信息把它们转化成了当前问题背景，而不是一上来就给操作建议？
2. 每个场景是否仍以“关键事实 + 现在做什么”为主？
3. 每个关键点是否能对应法律 / 监管要求、真实裁判争议或明确的证据风险？
4. 有没有漏掉消费者最容易因为图方便而无意识确认、同意、取消或接受的节点？
5. 最终经验是否真正告诉用户“下次从源头怎么少吃亏”，同时删掉了普通流程、重复解释和弱提醒？

第 1、第 3 或第 4 项明显有问题，不能发布。

---

一句话标准：

> **短而有用：先让用户一眼看懂这是什么问题；必要时用最新规则和典型问题迅速建立语境；再突出法律和真实争议会看的关键事实，提前阻止无意识让步，并在最后留下一个下次不再吃亏的经验。**

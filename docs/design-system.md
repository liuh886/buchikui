# 不吃亏 — 设计规范

> 版本：v2.0 | 更新日期：2026-08-14

## 设计方向

不吃亏不是政府办事门户，也不是律师事务所官网。视觉定位是 **editorial field guide / 消费事故现场手册**：信息密度高，但阅读秩序清楚；有明显态度，但不靠装饰制造“设计感”。

核心原则：

- **案卷感，而不是 App 控件感**：Case 编号、目录、步骤、证据都使用索引式排版。
- **少圆角、少胶囊、少阴影**：主要靠分隔线、留白、字号和色彩建立层级。
- **编辑部节奏**：大标题负责抓注意力，小号标签负责定位，正文保持克制。
- **证据优先**：黄色只用于证据和关键事实高亮，红色只用于风险、编号和关键品牌识别。
- **移动端不降级**：桌面 popover 在手机上变成底部目录抽屉，正文单列但保留信息层级。

## 色彩

| Token | 色值 | 用途 |
|---|---|---|
| Ink | `#171715` | 主文字、主按钮、强分隔线 |
| Paper | `#f6f3ec` | 页面背景 |
| Surface | `#fffdf8` | 弹层、模板等抬升表面 |
| Red | `#d94b3f` | Case 编号、风险、品牌识别 |
| Yellow | `#f2cf55` | 证据、选中态、关键事实高亮 |
| Muted | `#777168` | 次要文字 |
| Line | `#d7d0c4` | 常规分隔线 |
| Dark | `#1a1a18` | 行动卡、证据区 |
| Blue | `#3157d5` | 行政/规则提示和焦点状态 |

不使用渐变主视觉，也不再使用旧版紫色体系。

## 字体与层级

使用系统无衬线字体栈：`Inter / system-ui / PingFang SC / Microsoft YaHei`。

- Hero H1：桌面约 `58–104px`，移动端 `50–76px`，紧凑行高和负字距。
- Section H2：桌面约 `42–68px`，移动端约 `40–58px`。
- 正文：`14–22px`，按信息重要度分级。
- UI 标签：`9–12px`，高字重、适量 letter-spacing。
- Case 编号：红色、大号、独立成列。

## Case Switcher

Case Switcher 是全站最重要的全局交互之一。

### 桌面

- 当前 Case 直接作为导航入口，不使用胶囊容器。
- 结构：`CASE 编号 / Case 名 / 切换 / Chevron`。
- 打开后为目录式 popover，而不是卡片菜单。
- 当前项使用浅黄色底 + 左侧红色状态条。
- “随机一个”是轻量文本操作，不做高饱和按钮。

### 移动端

- 顶部只保留 Case 编号、名称和 Chevron。
- Case 目录变成底部抽屉，带遮罩。
- 抽屉固定到 viewport；移动端顶部栏不使用 `backdrop-filter`，避免 fixed containing block 错位。
- Esc、点击外部、点击遮罩均可关闭。

## 组件规则

### Button

- Radius：`6px`
- Primary：深色底 + 浅色文字
- Secondary：透明底 + 中性色边框
- 不使用 999px 圆角，不使用硬投影 hover

### Hero

- 红色 Case 标签 + 超大标题 + 一段核心说明
- 右侧行动卡保持深色，但不旋转，不使用夸张阴影
- 行动步骤使用 `01 / 02 / 03 / 04` 索引

### Scenario Locator

- 使用横向文本轨道，不使用一排 pill chips
- 每一项由分隔线组织，hover 用红色底部短线

### Scenario List

- 开放式列表，不用 card grid
- `编号 / 场景标题 / 行动与证据` 三列组织
- 移动端降为 `编号 + 标题`，正文块单列

### Evidence

- 深色整段区域，顶部红线
- 两列清单，移动端单列
- Checkbox 为小方框；完成态使用黄色

### Route

- 桌面四列步骤表，移动端纵向步骤流
- 不使用独立圆角卡片

### Template

- 白色文档表面 + 顶部深色规则线
- 轻微自然阴影，不使用漫画式 offset shadow

## 响应式

主要断点：

- `1060px`：收起正文导航
- `860px`：进入移动布局、Case Switcher 底部抽屉、内容单列
- `480px`：进一步压缩 Case Switcher、Evidence 元数据布局

要求所有关键页面在 `390px` 宽度下无横向溢出。

## 动效与无障碍

- 动效只用于 hover、Case 切换和弹层状态，不做装饰性动画。
- 遵守 `prefers-reduced-motion`。
- 所有 button/link 保留 `focus-visible`。
- Case Switcher 保留 `aria-expanded`、`aria-controls`、当前项状态和 Esc 关闭。

## 禁止项

后续新增 Case 或组件时不要重新引入：

- 紫色主色和多彩渐变
- 大量 pill / badge / bento 卡片
- 夸张硬阴影
- 旋转卡片
- 为装饰而存在的 icon rows
- 与正文无关的仪表盘式 chrome

设计系统应继续围绕“**内容可信 + 证据优先 + 编辑部秩序**”生长，而不是向通用 SaaS UI 演化。

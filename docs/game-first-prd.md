# Buchikui Game-first 产品重构 PRD

> 状态：**已确认的产品方向 / 待实现（Design target）**。2026-11-15。此文定义下一版本的目标，不声称主干运行版已经切换；当前问卷、schema 3、旧答卷及线上路由以现行代码和旧规范为准，直到迁移 PR 合并。本 PR **只新增规划与验收文档**，不修改站点、数据库或公开题库。
>
> 产品决策来自本轮用户讨论：Buchikui 首先是一款 **Wordle 式、每天五关、可以通关且有标准判定的真实消费决策游戏**。YES = 购买/接受这笔交易，NO = 拒绝/不买；选择以后揭示为什么不买，或者为什么被忽略的好东西值得买。真实 CASE 与众包构成内容引擎。

## 1. 北极星：游戏而非问卷

用户打开站点，直接看到第一张可购买场景卡；选择 YES/NO，立即知道判断结果，并经历一段可信、有反转、有证据的「真相揭晓」；五关后获得成绩与可分享的挑战卡，朋友以同一套未剧透的关卡挑战。玩家可以进入解锁的调查档案，继续追踪原始证据，也可提交现实中发现的消费素材。

承诺给玩家的是 **better buying decisions through surprising, verifiable truths**，不是民意调查、人格测试、随手曝光平台，也不是泛化法律问答。「买」始终是给定目标与题面事实下的决策，不宣称任何商品对所有用户一律应买/不买。

三种不同价值必须分开验证：**玩起来**（完成与续关）；**惊讶而信任**（反转后认可证据）；**愿意挑战朋友**（真实分享/到达）。把「把答案猜出来」与「能识别现实可见线索」分开，不能把二元猜测包装成消费能力测量。

## 2. 用户、入口与最短路径

默认用户：普通成年消费者，手机优先，既可能熟悉消费陷阱，也可能没有遭遇过；不要求提供真实个人遭遇。次要用户：贡献消费素材的普通人、核查者、编辑。首次进入不登录、不开导览、不让用户先选择形象或填写问卷。桌面保持单张卡视觉中心。

主路径：

1. **今日第 1/5 关**：展示真实可识别的商品/服务场景、价格或条件（如对判断重要）、用户的购买目标，以及可观察的疑点；禁止在题面透露标准答案。
2. **YES / NO**：左右手势与按钮等价，滑动阈值需避免把纵向滚动误判为选择；首次选择锁定该关计分，不能通过重玩改分。
3. **THE REVEAL**：直接出现对错 + 一句关键反转；展开最多两层线索，接着给对应权威来源或原始记录、结论适用边界、下次可复用的识别方法。
4. **下一关**：答错也能继续，不因第一次错误卡住；可以返回看证据，但不能替换首次得分。完成第 5 关后进入成绩页。
5. **成绩与传播**：0–5 分、五格不剧透结果、一个令人想分享的关卡钩子，挑战链接打开同一天同一套题的未答状态。
6. **调查档案 / 投稿**：非必做；档案保留完整 CASE 和一手来源，投稿进入待核查池而不是直接公开。

题面第一眼必须知道「是什么」「多少钱/什么条件」「要不要买」。不使用「你是否遭遇过」和「有过/没有过」的旧问卷文案。默认每关聚焦一个可改变消费决定的线索；不能凑法律背景、第二层标签或过长免责声明阻断游戏。

## 3. YES/NO 的“标准答案”条件

标准答案不是大众投票、编辑喜好或 AI 信心。只有当 **具体交易条件 + 消费者目标 + 可核验事实** 足以支持一个明确的较优选择，才允许发布判分题。

- **NO 闸门**：对准明确的价格/合同/资质/真实性/安全问题；说明「拒绝的是这笔交易的这些条件」，不能由单个商家的争议概括全品牌产品违法。
- **YES 闸门**：针对消费者已经给出的目标，有可比、可核验的正向价值（实际质量、总价、必要功能、来源、保障、可用性）；不存在未处理的重大风险。普通商家合法经营或某法院支持消费者权利，不足以证明某个具体商品“值得买”。
- **看得见的线索**：决定答案的主要事实至少有一条须存在于玩家购买时可能合理获得的材料（页面、背标、合同、产品参数、公开登记或可点开的授权）；**不许先藏住唯一判定事实，选完才告诉玩家**。
- **情境锁定**：必要时明确预算、用途和风险偏好；一题不能同时出现两个都合理的选择。无法锁定的主观性「值不值」退回调查档案，不参加计分。
- **证据可回溯**：题库内引用真实来源 ID、直接定位、核验日期和事实边界；原案争议、广告推断、商标归属、制造地与营销夸大须分别核验。AI 只能辅助整理，不自动宣判。
- **可撤题**：证据过期、商品下架、来源失效、对错分歧成立时从未来 Daily Pack 下线；已完成成绩只显示历史版本，不静默改答案。

正式判分题应经过反向评审：审查者试着为相反选项构造同样合理的理由；如果反方在题设内成立，必须改题或者撤题。盲测区分玩家误读和真正判断错误。

## 4. 每日五关：节奏、难度和输赢

- **5 关固定顺序**：热身 → 识破 → 正向反转 → 高难 → Boss；关卡顺序经过编辑，不随机拼凑。发布第一阶段目标为 3 个 NO、2 个 YES，实际供给不足时不能硬凑正向关，更不能把待核验案例当作 YES。
- **每日唯一正式局**：按 Asia/Shanghai（UTC+08:00）日期生成稳定 Daily Pack ID、内容 revision、五个稳定关卡 ID；首次作答计分。断网/刷新可恢复，未来联网提交必须幂等；未提供跨设备身份时只能保证同设备的一次正式成绩，不声称全站防刷。
- **成绩**：答对 +1，答错 +0；完成五关就是「已通关」，5/5 为完美，4/5 为优秀，3/5 为合格，0–2/5 仍可获得完整证据与分享。不给速度加分，避免催促点击；不得把 5/5 宣称为稳定的消费智商或防骗水平。
- **揭晓曲线**：先结果，后令人意外的关键事实，最后原始出处和边界。文本可在短屏上逐层展开但不强制看长文。
- **关卡难度**：依据可观察线索数量、反常识程度和真实盲测错误类型调整；目前没有任何可靠的用户难度数据，编辑「热身/Boss」只是编排假设。
- **特殊篇章**：旧「租车的一天」五段决策可将来作为周末篇；不与每日五个互不相关的判分题混为同一真实事件。

状态机最少包括：loading、ready、choice-locked、revealing、resolved、next、completed、paused-source-invalid。回退只影响查看视图，不撤销已锁分数；用户返回依据页面后能恢复题面/解释状态。严重来源失效要暂停该局，而不是自动把某个选项定成正确。

## 5. 传播：挑战卡比宣传文案更重要

每关可分享 **未剧透的场景链接**；整局可分享 5 格对错、得分、日期和随机无需泄露用户身份的挑战 URL。不嵌入答案、个人订单、提交素材或可回放的选项明细。好友进入同一天未答的题包，不继承发送者得分；过期链接指向锁定历史包的可玩回顾模式，并显著说明不计今日成绩，若历史包已撤题则只提供资料说明。

第一版不做公开个人主页、全球排行榜、好友关系、自动导出回答记录或分享诱导弹窗。成绩比较只在同 pack、同规则、真实采集范围成立；无跨设备集中汇总时不得宣称「超过 78% 玩家」。

角色资产复用已有六种插画和分享技术，但含义必须改变：角色是 **消费调查团 IP、主题、章节纪念**，不是通过旧问卷 YES 数量分配的能力人格。小海獭/水豚/浣熊/狐狸/团雀/云朵都不按聪明或错误率贬褒；成绩和角色收集分开。首轮先保留一个通关时出现的伙伴，不开发完整成长经济系统。

## 6. CASE / 题库 / 众包生产

保留已有 corpus、法律与案例权威层、独立 /c/<slug>/ 档案和搜寻入口。新的 Challenge 是 **从 CASE 里提炼消费时点决策**，不是直接把自述问卷改成有答案。现有 corpus 记录规模不是可玩的关卡数量；每个来源必须检查 caseId、出处、定位与判定边界。

建议新增 **editorial/challenges/**（人工审核的版本化定义）和 **editorial/daily-packs/**（审核的每日五关清单），数据结构最少：

| 字段 | 用途 |
| --- | --- |
| id、version、state | 稳定 ID、语义版本、draft/review/approved/blocked/retired |
| caseSlug、caseIds、ruleIds、sourceIds | 复用现有权威来源，不另立来源登记 |
| productSnapshot、goal、offer、observableClues | 当时用户真正看见什么、要实现什么 |
| prompt、answer、reason、counterfactual | 一个 YES/NO 问题，答案、反转和不成立的反例 |
| evidence、scope、verifiedAt、validUntil | 原文定位、司法/监管/实测材料的权重和新鲜度 |
| revealSteps、nextTimeSignal | 两阶段解释与一次可迁移的识别技巧 |
| levelRole、reviewer、reviewNotes | 编辑编排、独立复核与决定记录 |

模型可以先是版本化 JSON 和简单加载器，不要求引入 CMS。不要复写完整法源正文。必须把「历史真实案件」和「为易理解而重构的用户界面」分开标注，不能拼凑真实人物经历。

众包以 **素材发现 → 查证 → 关卡编辑 → 反方审查 → 发布** 作为状态流；社区可提出观点和证据，但不能靠投票决定法律/事实真假。涉及商家欺诈、来源造假、功效夸大时要求先证据后定性，允许更正、异议和下线。原有消费者反馈队列、GitHub 文案反馈和旧问卷回答三者不互混。公开玩家成绩数据的处理方式另做最小化隐私设计。

## 7. 与现有实现的隔离和迁移

当前 main 中 editorial/game-content.json 标记 mode=self-report；survey-state.js 与 scripts/lib/content-db.mjs **明确拒绝 answer/correctWhy/wrongWhy 等判分字段**。不得通过删除旧验证来硬塞 Challenge。旧问卷 schema 3 与 data/survey.sqlite 不迁移为游戏成绩，也不能将旧选择转化为消费能力。

建议新建 challenge 数据模型、判定与本地状态模块、每日题包编排、结果和分享；只抽取可复用的滑卡、恢复、dialog、图片导出和样式能力。首页切换必须在功能垂直切片、内容证据和发布验收满足后单独实施。保留 /c/<slug>/、资料库、来源链接、PWA 回退；旧问卷可作为自愿的「消费经历」次级入口，是否长期保留待游戏真实效果再决定。

**安全迁移约定**：新路由优先例如 /?play=daily 或 /daily/，首页改动独立发布；旧存储 Key 与游戏存储 Key 分离；切换前不触碰真实回答库和现有已发布内容。文档指向旧问卷的「无正确答案」表述在迁移前仍是 **当前运行事实**，不是下一产品的目标。

## 8. MVP 范围、成功标准、阶段验收

**R0（本次 PR）**：确认产品合同、资产映射、五关剧情稿和证据阻塞项；无运行时代码更改。允许五关中正向题作为明确标记的待核验槽位，但不得上线正式 Daily Pack。

**R1（第一条可玩垂直切片）**：实现一套在预览环境可玩、可以刷新恢复、首轮锁分、完成成绩、复制分享链接且点击可复玩的五关。在正向真实商品证据不足时，只能使用明确标注的内部试玩/非正式包。此阶段优先功能贯通，不以全站重构为前提。

**R2（内容发布）**：五个题面各通过事实、来源、反方、体验复核；至少两个为真实正向价值案例；完成移动端 390/320px、屏幕阅读器基本检查、错误恢复、原文链接、来源失效测试和分享冷启动。未达到时不发布真实每日判分榜。

**R3（真实验证与众包）**：约 6–8 名普通成年消费者无提示试玩；记录他们是否理解 Yes/No、能否说出选择理由、是否相信揭晓、是否主动完成、是否想分享。观察指标：首次开始率、关卡→关卡续玩率、5 关完成率、揭晓展开率、分享点击、好友到达率、次日回访率；均以**实际事件与明确分母**计算，暂不虚构目标值或统计成效。之后接入轻量投稿和审核。

阻断上线的错误：题目无法在给定条件下定唯一答案、无法解释为什么、来源失效/与记录不符、YES 关只是假想好物、标准答案与真实案件时间事实混淆、未能恢复/重复计分、分享剧透或泄露回答。

## 9. 明确不做与尚未验证

MVP 不做虚拟千元预算、商店购买链接导流、AI 自动打假结论、能力排名、付费解锁、实时玩家对战、复杂勋章经济、广泛商家黑榜。它们都有可能稀释真实决策+反转揭晓的核心体验。

尚未验证的假设：五关是否比无限刷更有留存、动物角色是否帮助分享、玩家是否能在下一次现实消费中迁移识别方法、众包是否能以足够低的审核成本持续供题。将这些作为实验，不把愿景写成已实现的事实。

## 10. 当前已发现的证据例外

在对首期关卡核对一手来源时发现：corpus/cases/case-consumer-prepaid-retail-deduction.json 指向最高法 2025-03-14 预付式消费典型案例 **案例四**，但其「退卡按门市原价倒扣条款无效」的断言并非该案例四的核心事实；官方案例四讨论的是**经营者未提供服务数量与价款证据时的举证责任**。须另查适用司法解释及符合事实的裁判依据并修订语料，在完成之前不能从该记录生成正式判分题；参见 https://www.court.gov.cn/zixun/xiangqing/459331.html 。本次不暗改旧语料或重写旧问卷结果。

另有 2026-11-07 品牌产地线索文件明确标记 **未核查、不得指控具体品牌**：tasks/consumer-portrait/brand-origin-lead-2026-11-07.md 及 false-origin-brand-impersonation-lead-2026-11-07.md。它们适合作为调查主题，绝不能直接做「某品牌是假洋品牌」的标准答案题。

# 不吃亏 — 产品体验规范

状态：Normative · 更新：2026-10-24。可爱消费者经历角色版本已本地实现，待真实设备与用户验收，尚未发布。需求依据见[PRD](consumer-portrait-prd.md)，技术方案见[架构文档](consumer-portrait-architecture.md)。

## 1. 定位与参与收益

产品主张：测测你的消费经历角色，不花钱，也买教训。

经验较丰富的用户通过本次答卷获得可记住、可核对的可爱角色；经历较少的用户通过真实案例认识尚未遇过的消费波折。同一条简短流程服务两种收益，不要求开头自选老手或新手。

角色描述这份答卷的经历主题，不推断稳定人格、消费能力、防骗水平或法律责任。YES表示报告过具体遭遇，不能推导损失金额或吃亏次数；NO不能证明没有风险、没有消费接触或更有能力。

## 2. 首页与填写

首页直接出现一张问卷卡，不设登录、身份选择或介绍门槛。辅助文案说明完成后的角色与案例收获，轻量题号表明剩余工作量，不做得分或游戏进度条。

- 每题开头固定为“你是否遭遇过：”，仅问一个实际消费遭遇，目标不超过60字；标题只写具体场景。
- YES有过、NO没有过等色等权；右滑为YES、左滑为NO，点击与键盘语义一致。
- 任一选择记录后直接下一题，允许暂不回答和上一题修改，不判对错、不重答解锁。
- 题中小字“案例解析”主动打开原案、结果、边界、解释和原文；关闭返回同题，回答与进度不变。
- 当前八题按旅游订房、办卡报名、购买售后三组固定编排，一次连续填写，不循环重开。原案不编成受访者自身的故事。

NO与skip含义独立。当前未采集消费接触分母，因此不计算消费风险率，也不把分组YES比例解释成消费能力。

## 3. 画像与结果回报

结果层级：角色插画和名称 → 一句话理由 → 可核对的题项依据 → 两则具体案例与提醒 → 折叠的个人记录、答卷汇总和资料库。

六角色为守约小海獭、约定小水豚、细致小浣熊、故事小狐狸、初见小团雀和留白小云朵。它们同等精致，没有能力高低或稀有等级。角色命名和可爱偏好尚需真实受访者验证。

完成整卷后，至少6题非skip且每个经历机制至少1题非skip，才细分前五类；否则为留白小云朵，可补充回答。满足覆盖且YES为0时为初见小团雀，表述本次未报告题面遭遇，不称新手、幸运或谨慎。有YES则按各经历机制（承诺落差、安排变动、结算受阻）的YES/固定题数映射，整数交叉相乘比较，最大值并列为故事小狐狸。比例仅用于编辑映射，不作为风险指标显示。

“为什么是这个角色”列出当前实际YES题项，归一化主题不等于绝对题数最多。修改回答后重算，不能拼入已撤回的旧记录。覆盖不足、全NO和全skip均保留完整视觉与案例回报；skip不写成“没遇到”。

两则回报优先匹配当前YES经历（主画像时首则严格命中主机制YES，并列时两则分别严格回应两个并列胜出的机制），再用不同机制的审核入门案例补足；按机制、原案与规则去重。短读保留发生了什么、原案结果、适用边界、具体提醒和原始出处。提醒不能依据角色自由生成，不强制读完，不声称已掌握或已避免风险。

## 4. 分享与隐私

用户主动生成角色卡后先预览，再选择保存图片或系统分享。卡片仅含公共角色模板、品牌和干净问卷入口；不含实际YES/NO、答题数、具体遭遇、答卷标识或他人统计。预览说明角色会随卡片公开。图片在客户端Canvas生成，不上传、不建设公开个人结果页。

普通链接不编码角色或回答，公共OG保持通用；接收者从整卷首题开始。历史题号入口提供轻提示和对应案例入口，也从完整问卷开始，既有章节锚点继续有效。系统分享、剪贴板或下载不可用时提供保存/打开大图/手动复制后备。

## 5. 内容、版本与保存

问句与固定顺序在editorial/game-content.json；角色和审核短读在editorial/consumer-portraits.json。真实来源沿用corpus与legal-updates.js，不新建重复法源登记。

公开内容与状态使用schema 3。有效完整schema 2答卷可逐题核对后迁移，中途截断状态不能冒充整卷画像。问句语义改变隔离旧版本；画像规则独立版本，插画和案例说明变化本身不使原回答失效。

浏览器先保存，本机同步至独立data/survey.sqlite；可重建data/content.sqlite不删除回答。仅保存随机去重标识、题目/版本、选择、修改顺序与接收时间，不收姓名、联系方式、订单号、IP或设备指纹。分享、GitHub措辞反馈与公开统计不带个人答卷。

有效完整答卷聚合只包括当前全部问句版本都有记录且至少一题YES/NO的答卷；这与画像覆盖门槛独立。使用“份答卷”，不称核验独立人数、不做排名。当前仅本机范围，集中云收卷仍为P1。

## 6. 案例资料库

五卷十八章按书式阅读组织，保留搜索、折叠筛选、/c/<slug>/固定地址、规则锚点、前后章与返回问卷。默认阅读路径为现实问题 → 权威依据/裁判参考 → 现实提醒 → 必要时的证据与处理路径 → 原文。

原案、权威材料与Buchikui提醒分开；普通个案不能写成普遍退款保证。消费者反馈遵守consumer-feedback，Reader投稿入口继续退役；题面反馈走GitHub issue，不携带用户答案。

## 7. 视觉、离线与验收

单卡、暖纸色、清楚的中文排版与少按钮保留；结果增加统一圆润角色插画与柔和辅色，不引入正误或等级色。390px无横向溢出，触摸目标至少44px；插画失败有文字替代，减少动态与大字不丢信息。

角色资源按内容哈希发布，问卷壳、数据、脚本、样式与插画由版本化SW整包缓存；新包安装成功后切换，不能逐文件污染旧包。原文外链不承诺离线可打开。

[现行验收清单](release-acceptance.md)记载已完成的headless Edge验证，以及仍待真实手机、读屏、系统分享和6–8人理解/可爱偏好验证。工程绿色不能替代人工验收。旧游戏验收已归档，不再规定现行流程。

# 不吃亏 — Product Experience SPECS

> 状态：Normative  
> 更新：2026-09-18

## 1. 产品定义

“不吃亏”是一个**消费普法平台**。

它不替用户完成一套 AI 式纠纷诊断，也不追求把每个 CASE 做成完整维权工具。它从公开、可核验的权威材料中提取现实交易里最容易忽视、但可能改变结果的关键点。

核心链路只有一条：

**现实交易场景 → 权威依据 → 关键事实 → 现实提醒。**

纠纷已经发生时，才继续给出必要的证据和处理路径。

## 2. 首页

首页是主题资料库，不是随机 CASE 阅读器。

默认结构：

1. 一句话说明产品价值；
2. 搜索框；
3. 最近更新的高价值主题；
4. 全部消费场景。

首页不展示 CASE 编号、英文标签、随机按钮、Dashboard 指标、完成度或推荐算法感的 UI。

## 3. CASE 页

默认结构：

1. **现实问题**：普通消费者能直接看懂的标题与一段说明；
2. **权威依据**：法律法规、司法解释、部门规章、监管文件、典型案例或裁判；
3. **现实交易提醒**：典型场景的关键事实 + 消费者应留意的动作；
4. **证据**：只有该 CASE 确实需要时显示；
5. **处理路径**：只有纠纷继续升级时显示；
6. **原文**：一手来源和适用边界；
7. **一句可迁移经验**。

模板、Discussion、进度条、打卡、随机切换等不进入默认阅读路径。

## 4. 权威依据

用户可见名称统一使用：

- **权威依据**：法律、行政法规、司法解释、部门规章、监管文件等；
- **裁判参考**：指导案例、典型案例、普通裁判等。

必须明确：来源类型、机关 / 法院、文件 / 案号、生效或裁判时间（如有）、原文链接。

Buchikui 的解释不能伪装成法条原文；普通裁判不能被写成普遍法律规则。

## 5. 视觉语言

页面应像一个可信的编辑型普法资料库：纸张感、强排版、少卡片、少按钮、少状态 UI。

优先使用：标题、细线、列表、文献式元信息。

避免：大面积彩色卡片、发光按钮、仪表盘、数字进度、游戏化状态、密集 icon、AI 助手口吻。

## 6. 移动端

390 px 宽度必须：

- 无横向溢出；
- 首页首屏可看到产品定位和搜索；
- CASE 首屏可看到问题标题和说明；
- 权威依据允许纵向堆叠；
- 无固定底部双 CTA；
- 触摸目标保持可用，但不为了按钮感放大视觉噪音。

## 7. Definition of Done

发布前检查：

1. 页面入口是不是现实问题，而不是法律名词？
2. 关键结论有没有一手出处？
3. 是否清楚区分规则、裁判和 Buchikui 的现实提醒？
4. 有没有仍然像“AI 给我做诊断”的模块？有则删除。
5. 对用户没有决定价值的信息能不能删？
6. 是否保留了真正影响责任、授权、证据和救济的事实？
7. 原文能否直接打开？
8. 首页搜索能否快速找到相近消费场景？

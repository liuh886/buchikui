# 不吃亏 / Buchikui — Product Experience SPECS

> 版本：v1.6  
> 状态：Normative  
> 更新日期：2026-08-21

## 1. 产品定义

“不吃亏”是一个 **消费风险识别 + 动态权利更新 + 证据留存 + 行动路径** 产品，不是法律百科、政务门户、法律新闻站或长篇知识文章。

用户来到一个 CASE，只需要尽快回答六个问题：

1. 我遇到的是什么问题？
2. 现在先做什么？
3. 最近有没有新规则改变我现在可以要求什么？
4. 哪些事实会影响责任判断？
5. 哪些证据要马上保存？
6. 协商不成下一步找谁、怎么说？

页面不能因为追求“完整”而把这些问题埋进目录、说明、标签和重复章节里。

### Living CASE

每个 CASE 都是会随法律、监管、司法解释、平台规则和高价值裁判变化而更新的 **Living CASE**。

法律更新不是单独的新闻栏目。权利校验只展示当前对该 CASE 真正有行动价值的关键规则，并完成这次翻译：

**规则 / 裁判 → 消费者问题 → 当前关键权利 → 现在可以要求什么。**

默认单条；只有存在 2–4 个彼此独立、都足以改变消费者动作的关键权利问题时，才使用 Tabs。具体准入、法源权重、效力和裁判纪律只以 `docs/legal-freshness-standard.md` 为准。

更完整的依据继续留在 Sources，不把正文变成法规时间线。

## 2. 唯一阅读路径

Standard CASE 默认只有一条主路径：

**一句主张 → 3–4 个立即动作 → 权利校验 → 场景列表 → 关键证据 → 处理路径 → 按需模板 → 按需讨论 → 来源 → 最终经验**

其中：

- Hero 负责说人话，不承担法律说明；
- 权利校验负责关键法律点，不承担完整场景叙事；
- 场景列表负责典型问题和行动提示；
- “正常服务基线”等辅助判断模块只有确实必要时存在，并默认折叠；
- 沟通模板属于工具，不占据默认阅读主线，默认折叠；
- Discussion 只在确有公共治理 / 产品机制价值时出现，不是必填模块；
- Sources / Disclaimer 留在底部，不与行动内容争夺视觉层级。

不要新增第二套目录、重复 CTA、独立 dashboard、说明性 chrome 或只用于解释页面结构的 UI。

## 3. Header

Header 只保留：

**品牌 / 当前 CASE 切换 / 分享**

Case Switcher 的关闭状态只显示 **当前 CASE 名称 + Chevron**。CASE 编号、英文标签、随机入口等信息只在展开后的案例目录里出现。

不再提供常驻的“典型场景 / 证据 / 路径 / 模板”页内导航。页面本身是一条线性行动路径。

## 4. Hero、立即行动与权利校验

### Hero

Hero 只承担两件事：

1. 一个强、短、可记忆的主张；
2. 一段问题定性，让第一次进入页面的用户立刻知道发生了什么、为什么与自己有关、本文解决什么。

**Hero 最重要的是说人话。** 不从法规名称、年份、政策沿革或抽象责任结构起笔。

Hero 不再重复显示 CASE stamp、目录提示或下一步导航。

### Immediate Actions

通常保留 3–4 项跨场景都成立的高优先级动作。

默认只展示动作标题；详细解释放到后续场景、证据或路径中。只有标题本身无法避免用户做错关键动作时，才增加一行必要说明。

优先提醒那些现在一旦做错、以后很难补的动作。

### 权利校验

Hero / Immediate Actions 后允许存在轻量 Rights Check，只回答：

**这个场景背后，当前最关键的规则给了我什么抓手？**

它必须：

- 明确显示 **现行 / 即将生效**，不得把未来规则写成今天已经享有的权利；
- 显示来源权重，例如 `司法解释 / 部门规章 / 监管典型案例`；
- 规则有明确生效日期时显示实施日期；
- 显示法律核验日期；
- 先给消费者判断，再给必要法律解释；
- 给出一条当前可执行动作；
- 优先链接官方 / 一手来源；
- 不重复 CASE 正文已经完整解释的背景。

它不能：

- 变成法律新闻列表；
- 为视觉统一硬凑 Tabs；
- 用普通个案判决写成普遍法律结论；
- 只摘法条、不告诉用户下一步做什么；
- 用“新规”两个字掩盖尚未生效的时间状态。

单条还是 Tabs，以 `docs/legal-freshness-standard.md` 为唯一依据。

## 5. 场景是核心单位

复杂纠纷继续采用 **Scenario-first**。

场景标题使用用户自然语言，例如：

- 到店没车
- 临时换车
- 被验损扣钱
- 做完才说要加钱
- A 换完没修好，又说 B、C 也坏了

每个 Standard CASE 场景默认只保留：

- **关键事实**：真正改变责任、证据、授权或金额判断的事实；
- **现在做什么**：对象 + 动作 + 要得到 / 保存的结果。

场景负责指出典型问题并给行动提示，不承担系统普法。默认不再单独显示 `risk` 副标题。`short` 只作为内容数据中的稳定场景名称，不再额外制造一个可见层级。

只有当新信息会改变用户动作、证据或处理路径时，才新增场景。

## 6. Progressive Disclosure

Buchikui 默认采用“主线展开、辅助信息收起”。

### 默认展开

- Hero
- Immediate Actions
- 权利校验
- 场景正文
- Evidence
- Route
- Discussion（仅在确有内容时）
- Sources / Takeaway

### 默认折叠

- 正常服务基线等辅助背景模块
- Communication Template

折叠不是删内容。会决定投诉、调解或诉讼结果的事实仍然必须保留，只是不让辅助信息抢占第一阅读层。

## 7. Evidence

Evidence 保留可勾选状态和进度。

每项只显示：

**材料名 + 必要的一句用途说明 + 确有价值时的时间提示**

分组可以保留，但分组说明默认不显示。不要把证据清单写成第二篇文章。

新规则改变举证责任时，Evidence 应优先告诉用户：**证据在谁手里，以及应该向谁明确索取。** 不再默认所有证据都由消费者自己想办法寻找。

## 8. Route

Route 是简洁的升级路径，不是新的大章节。

每一步回答：

**什么时候升级 → 找谁 → 带什么 → 要什么结果**

默认不再额外显示 kicker 和长篇 section intro。重要条件可以留在 step 或 route note。

监管或申诉规则有明确前置投诉要求、答复期限或受理时限时，必须保留，因为错过可能直接改变用户的救济位置。

## 9. Template

模板默认折叠，只露出明确的“查看 / 复制”入口。

展开后保留：

- 必要的一句使用说明；
- 完整模板正文；
- 复制操作。

不要为了展示工具而让模板永久占据整屏。

当新规提供新的程序权利，例如要求平台说明事实 / 理由 / 依据、要求人工复核、要求提交其控制的证据，模板应优先把这些权利翻译成可以直接复制的请求。

### 9.1 Discussion

Discussion 是可选末段模块，放在行动内容之后、Sources 之前。

它只讨论：**这个 CASE 暴露了什么值得产品、平台或行业继续改进的机制。**

要求：

- 保持轻量，不再增加一套操作流程；
- 2–4 个短段落即可；
- 明确区分现行法律义务和 Buchikui 的治理建议；
- 不为每个 CASE 强行增加。

## 10. Compact CASE

Compact CASE 继续保持：

**一句主张 → 约 3 个关键理由 / 条件 → 权利校验 → 3–4 步处理 → 按需 Discussion → 来源 → 最终经验**

不要为了和 Standard CASE 形式一致而补齐无用模块。

## 11. 移动端

移动端优先保证：

- 首屏能看到主张和立即动作；
- 权利校验保持紧凑，单条或少量 Tabs 都不能制造新的卡片流；
- 法律状态、权重、日期在窄屏允许换行，但不能被隐藏；
- Header 只保留品牌 + CASE 名称；
- 底部操作只保留“找到我的问题 / 查看处理步骤”和“分享 CASE”；
- 390px 宽度无横向溢出；
- Case Switcher 使用底部抽屉；
- 折叠模块使用原生 `details/summary`，键盘和触摸均可操作。

## 12. 发布前验收

发布或修改 CASE 前只检查：

1. 首屏是否马上说清这是什么问题，而且是普通人能听懂的话；
2. 权利校验是否真会改变用户动作，而不是为了显得“新”；
3. 现行 / 即将生效、法源权重和实施日期是否表达准确；
4. 默认可见层是否只有一个阅读主线；
5. 每个场景是否仍然是“典型问题 → 关键事实 → 现在做什么”；
6. 是否保留了会改变责任、证据、授权、损失金额或诉讼结果的关键节点；
7. 是否检查了当前有效规则、新近司法解释 / 部门规章 / 高价值裁判；
8. Discussion 如存在，是否简短并明确区分法律要求和治理建议；
9. 辅助说明是否能折叠或删除，而不是继续 append；
10. 用户是否能顺着页面完成“判断 → 留证 → 升级 → 表达诉求”的闭环。

核心原则：

> **简化解释，不简化决定结果的过程；更新法律，不堆积法律。**

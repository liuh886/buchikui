## 2. 执行与记录方式

每次人工验收记录日期、构建提交或内容revision、问卷/画像版本、URL、设备型号、系统/浏览器版本、视口、系统字体/缩放、读屏与减少动态设置。状态为待执行/通过/失败/不适用，并附截图、录屏或实际播报记录。模拟浏览器与真实设备分栏记录。

至少覆盖一部iPhone Safari + VoiceOver、一部Android Chrome + TalkBack。只打开分享面板再取消即可验收入口，不要求向他人发送消息。本清单不自动招募或发送邀请。

## 3. 真实手机填写与阅读

- [ ] 无引导打开首页，辨认在问自己的遭遇；首题、YES/NO及案例入口可达。
- [ ] 点击与真实左右滑动语义一致，短拖/缩回/纵向滚动/系统取消不误答，双击不连续跳题。
- [ ] YES、NO、skip都可继续，上一题修改、刷新、章节往返保留正确进度与当前答案。
- [ ] 每题案例解析关闭后回到当前入口；结果的案例阅读返回仍在原结果，不新增回答。
- [ ] 六角色、全NO、全skip、混合、覆盖不足及并列结果可理解，未回答不写成没遇到。
- [ ] 390px、横竖屏、系统大字/200%缩放无横向溢出、遮挡或丢失关键边界。
- [ ] 图片加载失败与离线时角色文字、具体提醒、返回/修改入口仍可用。

## 6. 真实受访者理解与可爱偏好

安排6–8位普通成年消费者，覆盖经历较多与较少者。经同意记录，不收真实订单、身份或纠纷隐私。人数门槛采用ceil(0.75×n)：6人需5人、7人需6人、8人需6人；小样本发现问题，不用于声明总体效果。

- [ ] 不口头解释即可理解问亲身经历并自行开始。
- [ ] 能用自己的话解释角色依据，不把YES多理解成笨、强或等级高；关键误解出现即修改并复查。
- [ ] 能复述至少一条与原案边界一致的提醒，找到原文入口。
- [ ] 记录喜欢/无感/不喜欢与原话，达到上述人数愿意保留形象；不以实现分享按钮冒充可爱偏好。
- [ ] 记录哪些题不相关、NO是否因未消费、何处困惑，以及保留/改写/撤题决定。

## 1. 契约目标与角色映射

本契约用于约束消费者画像的可计算性、证据线索提取、案例推荐对齐与展示边界。角色完全基于**本次答卷自述的经历机制**生成，绝不推断人格类型、消费能力或心理成熟度。

### 角色映射定义

| 角色标识 | 可爱形象 | 对应经历机制 / 结果状态 | 一句易记的描述 | 支撑题项范围 |
| :--- | :--- | :--- | :--- | :--- |
| `otter` | **旅途小海獭** | **机制 A：承诺与实际不符**（宣传/承诺履行不对板） | “说好的与实际给的，在这次记录里遇到了落差。” | Q1(无购物加点)、Q7(换新变零件)、Q8(闲置变假货) |
| `capybara` | **约定小水豚** | **机制 B：服务安排被改变**（流程/地点/扣款单方变更） | “原本约定好的安排，在消费过程中被单方面调整。” | Q2(到店付变预扣)、Q5(培训迁址) |
| `raccoon` | **购物小浣熊** | **机制 C：预付与结算受阻**（退订受阻/停业清算波折） | “预付的权益与未做项目，在结算退款时遇到了阻碍。” | Q3(健身停业退费)、Q4(年卡闭店)、Q6(写真退订未做) |
| `fox` | **故事小狐狸** | **并列 / 混合经历**（多机制势均力敌） | “几组不同的消费经历，在这次答卷里都留下了波折线索。” | 跨机制多项 YES 且最高比例并列 |
| `bird` | **初见小团雀** | **未报告遭遇**（全部有效回答均为 NO） | “这次列出的常见消费波折，你暂时都没有遇到过。” | 全 NO（无任何 YES） |
| `cloud` | **留白小云朵** | **覆盖不足**（跳过较多，有效回答低于门槛） | “先留出一点空白，回答还不足以为你生成明确的经历特征。” | 有效回答数 $< 6$ 或单机制有效回答 $< 1$ |

## 2. 确定性计算规则与判定算法

### 2.1 输入定义
- 答卷响应列表：按 8 题顺序输入 `choices = [c1, c2, ..., c8]`，每个 $c_i \in \{\text{'yes'}, \text{'no'}, \text{'skip'}\}$。
- 各题所属机制集合：
  - $\mathcal{M}_A = \{\text{Q1}, \text{Q7}, \text{Q8}\}$（容量 $T_A = 3$）
  - $\mathcal{M}_B = \{\text{Q2}, \text{Q5}\}$（容量 $T_B = 2$）
  - $\mathcal{M}_C = \{\text{Q3}, \text{Q4}, \text{Q6}\}$（容量 $T_C = 3$）

### 2.2 状态判定流程
1. **有效性与覆盖门槛检查**：
   - 统计非 `'skip'` 的有效回答总数 $N_{\text{answered}}$。
   - 统计各机制内非 `'skip'` 的有效回答数 $N_A, N_B, N_C$。
   - 若 $N_{\text{answered}} < 6$ 或 $\min(N_A, N_B, N_C) < 1$，状态返回 `insufficient`，画像为 `cloud`（留白小云朵）。
2. **未报告遭遇检查**：
   - 提取所有回答为 `'yes'` 的题目集合 $Y$。
   - 若 $|Y| = 0$（且满足覆盖门槛），状态返回 `no-reported`，画像为 `bird`（初见小团雀）。
3. **经历机制得分与比较**：
   - 计算各机制内 `'yes'` 的数量：$Y_A = |Y \cap \mathcal{M}_A|$，$Y_B = |Y \cap \mathcal{M}_B|$，$Y_C = |Y \cap \mathcal{M}_C|$。
   - 经历比例比较采用**整数交叉乘法**，避免任何浮点精度问题：
     - $A$ 与 $B$ 比较：$Y_A \times 2$ 与 $Y_B \times 3$
     - $A$ 与 $C$ 比较：$Y_A \times 3$ 与 $Y_C \times 3 \iff Y_A$ 与 $Y_C$
     - $B$ 与 $C$ 比较：$Y_B \times 3$ 与 $Y_C \times 2$
   - 找出得分比例最高的所有机制集合 $\mathcal{W}$：
     - 若 $|\mathcal{W}| = 1$：唯一最高者胜出，分别对应：A -> `otter`，B -> `capybara`，C -> `raccoon`。
     - 若 $|\mathcal{W}| \ge 2$：出现最高分并列，画像为 `fox`（故事小狐狸）。

## 3. 证据线索与理由提取规范

结果页的理由展开区**必须客观呈现答卷本身的自述**，禁止空洞描述：
1. **单一机制画像（otter / capybara / raccoon）**：
   - 从胜出机制的 $Y_X$ 中，按题目出现顺序提取线索：
     - 若 $|Y_X| \ge 2$：提取前 2 项作为线索点（例如：“报名无购物团却多了玉石博物馆”、“买电池换新承诺变成了换零件”）。
     - 若 $|Y_X| = 1$：提取该 1 项，并在下方清晰注明：“本画像基于本次单项经历线索生成，线索较聚焦；可继续体验其他场景”。**严禁凭空编造第二条线索**！
2. **并列画像（fox）**：
   - 从并列胜出的机制中，各取其题序最靠前的 1 项 YES 作为证据线索（形成 2 条跨机制的鲜明证据）。
3. **初见小团雀（bird）**：
   - 展示中性提示：“本次调研的 8 项常见消费经历中，你本次均未遇到。可阅读下方精选案例提前了解。”
4. **留白小云朵（cloud）**：
   - 展示中性提示：“本次有效回答题数不足（暂不回答多于 2 题），先不归入特定经历特征。可阅读下方精选案例。”

## 4. 案例回报（Lessons）与主画像对齐规则（解决 F02 错位）

推荐 2 则且仅 2 则案例，严格按以下两级规则选取：

### 规则 1：第一则案例（Primary Lesson）必须对齐主画像
- **正常角色（otter / capybara / raccoon）**：第一则案例必须来源于主画像证据线索中的首个有效 YES 题所绑定的案例！
- **并列角色（fox）**：第一则案例取并列胜出机制中第一个机制的首个 YES 题案例。
- **初见小团雀（bird）/ 留白小云朵（cloud）**：第一则案例取全局 `introPriority` 最高的中性案例（如 Q1 旅游案例）。

### 规则 2：第二则案例（Secondary Lesson）促进跨场景迁移
- 从剩余候选案例中选取：
  - **优先匹配答卷中其他未被第一则使用的 YES 题**（优先选择与第一则所属机制不同的题，避免两则案例完全讲相同的事，兼顾交易场景多样性）。
  - 若用户没有其他 YES 题（如用户总共只有 1 个 YES），则从其他机制中按 `introPriority` 选出一则高质量中性入门案例。
  - 去重约束：两则案例必须满足 `caseId` 互斥，且 `topicSlug/ruleId` 互斥。

## 5. 六个典型场景全用例验证规范（Ground Truth Test Cases）

### 用例 1：机制 A 胜出（旅途小海獭）
- **输入**：`['yes', 'no', 'no', 'no', 'no', 'no', 'yes', 'no']`（Q1有、Q7有，其余无）
- **机制得分**：A = 2/3 (66.7%), B = 0/2 (0%), C = 0/3 (0%)
- **预期角色**：`otter`（旅途小海獭）
- **证据线索**：2条（Q1无购物加点，Q7换新变零件）
- **推荐第一则**：Q1 无购物加点（对齐主画像证据）
- **推荐第二则**：Q7 换新变零件（或另一跨场景相关案例）

### 用例 2：机制 B 胜出（约定小水豚）
- **输入**：`['no', 'yes', 'no', 'no', 'yes', 'no', 'no', 'no']`（Q2有、Q5有，其余无）
- **机制得分**：A = 0/3, B = 2/2 (100%), C = 0/3
- **预期角色**：`capybara`（约定小水豚）
- **证据线索**：2条（Q2到店付变预扣，Q5培训迁址）
- **推荐第一则**：Q2 到店付变预扣（对齐主画像证据）
- **推荐第二则**：Q5 培训迁址

### 用例 3：机制 C 胜出与历史错位复现用例验证（购物小浣熊）
- **输入（PM审计复现用例）**：`['no', 'yes', 'yes', 'no', 'no', 'yes', 'yes', 'yes']`（Q2, Q3, Q6, Q7, Q8 为 YES）
- **机制得分**：
  - A (Q7, Q8) = 2/3 (66.7%)
  - B (Q2) = 1/2 (50.0%)
  - C (Q3, Q6) = 2/3 (66.7%)
  - *注：此用例在原模型判定为售后组胜出，在经历模型中 A 与 C 并列 2/3，判定为 fox。*
- **纯粹机制 C 胜出用例**：`['no', 'no', 'yes', 'yes', 'no', 'yes', 'no', 'no']`（Q3, Q4, Q6 为 YES）
  - 机制得分：A = 0/3, B = 0/2, C = 3/3 (100%)
  - **预期角色**：`raccoon`（购物小浣熊）
  - **推荐第一则**：必须为 Q3/Q4/Q6 之一（如健身闭店或儿童乐园年卡），**绝不推荐到店预扣或旅游加点**！

### 用例 4：单一 YES 触发（线索有限样例）
- **输入**：`['no', 'no', 'no', 'no', 'yes', 'no', 'no', 'no']`（仅 Q5 为 YES，其余 NO）
- **机制得分**：A = 0/3, B = 1/2 (50%), C = 0/3
- **预期角色**：`capybara`（约定小水豚）
- **证据线索**：恰好 1 条（Q5 培训迁址），显式标注“线索有限，基于单项经历生成”。
- **推荐第一则**：Q5 培训迁址案例。
- **推荐第二则**：从机制 A 或 C 中选取一则入门案例（例如 Q1 旅游或 Q4 年卡）。

### 用例 5：并列最高分（故事小狐狸）
- **输入**：`['yes', 'no', 'no', 'no', 'no', 'no', 'no', 'no']` 加上 `['no', 'yes', 'no', 'no', 'no', 'no', 'no', 'no']` 无法直接并列（1/3 vs 1/2）。
- **等比并列输入**：`['yes', 'no', 'no', 'no', 'no', 'no', 'yes', 'no']`（A: 2/3）与 `['no', 'no', 'yes', 'yes', 'no', 'no', 'no', 'no']`（C: 2/3），B为0。
- **机制得分**：A = 2/3，B = 0/2，C = 2/3。A 与 C 交叉相乘 $2 \times 3 = 2 \times 3 = 6$ 并列最高。
- **预期角色**：`fox`（故事小狐狸）
- **证据线索**：2条，分别取自 A（Q1）与 C（Q3）。
- **推荐案例**：第一则取 Q1，第二则取 Q3，完美覆盖两个并列经历。

### 用例 6：全部没有过（初见小团雀）
- **输入**：`['no', 'no', 'no', 'no', 'no', 'no', 'no', 'no']`
- **预期角色**：`bird`（初见小团雀）
- **推荐案例**：2则高质量中性入门案例（如 Q1 旅游 + Q4 预付年卡）。

### 用例 7：跳过较多覆盖不足（留白小云朵）
- **输入**：`['skip', 'skip', 'skip', 'yes', 'no', 'no', 'no', 'no']`（有效回答仅 5 题 $< 6$）
- **预期角色**：`cloud`（留白小云朵）
- **推荐案例**：2则中性入门案例。

## 6. 版本控制与数据保护

1. 画像规则版本定义为：`portrait-2`。
2. 架构与数据库升级要求：
   - 旧答卷保留其填写时的历史状态，不强行按新规则篡改历史记录。
   - 用户刷新页面或再次完成问卷时，无缝应用 `portrait-2`。
   - 绝不因算法重构导致已保存的用户答卷库 `data/survey.sqlite` 产生脏数据或记录丢失。

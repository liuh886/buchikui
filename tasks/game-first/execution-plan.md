# Game-first 执行路线、资产复用与验收清单

> 状态：实施计划，2026-11-15。由 [产品 PRD](../../docs/game-first-prd.md) 与 [Episode 001](episode-001.md) 驱动。**本次只交付文档，不修改当前运行游戏、不发布、不迁移旧用户数据。**
>
> 核心原则：优先做出「真实可玩的五关 + 真相揭晓 + 成绩分享」垂直切片。拒绝以整理目录、补大量断言或扩大文案替代核心功能；涉及事实/判定/数据状态的关键路径则必须严格验收。

### 角色的最小用法

- 小海獭：承诺与实际交付；水豚：预约/服务安排；浣熊：价格/费用；狐狸：品牌/来源；团雀：被忽略的好物；云朵：调查提示。
- 只是 **主题 IP 工作定义**，不是从既有调查中科学推断的消费人格。首版只让角色出现在揭晓或成绩页，不必一次开发六套成长机制。
- 当前资源路径可能在构建后带内容哈希；游戏消费该资源 manifest，不复制/重命名二进制图片。

## B. 并行任务与真实依赖

| ID | 交付 | 最短实现 | 验收方式 | 阻塞 |
| --- | --- | --- | --- | --- |
| G0 | Game-first 目标合同 | 本次 PRD、Episode、执行计划、文档/Agent 入口 | 读者明确目标态和主干现状不同 | 无 |
| G1 | 独立 Challenge 模型 | editorial/challenges、daily-packs、validator、public serializer | 旧问卷不变、有效关卡通过、证据不足关卡不可发布 | G0 |
| G2 | 五关状态机与页面 | 新 game engine + 简洁单卡 UI、揭晓与下一关 | 刷新恢复、首次锁分、断网恢复、0–5分一致、回退只读 | G1；可用内部素材 |
| G3 | 成绩卡和挑战链接 | 复用图片导出/原生分享的可靠回退 | 无剧透、好友新开局、过期历史包口径明确 | G2 |
| G4 | 内容验收与首集上架 | 核实 Level 1/3/5，补齐两条 YES 的真实实物与比较依据 | 五关每题反方审查、真实核验、线索可见、负面指控准确 | G1；可以与 G2 并行 |
| G5 | 首页切换与发布 | 主入口指向 Daily 5；文档、SEO/OG、PWA、旧问卷入口同步更新 | 新用户直接第一题；/c/<slug>/ 不断链；旧回答不丢；可回滚 | G2+G3+G4 |
| G6 | 轻量众包 | 投稿素材+证据链接，待核查/被退回/获采纳状态 | 无审核直接公开不可达，隐私和版权处理可解释 | G5 或并行设计 |

**优先顺序**：G1→G2→G3 构成可玩的技术垂直切片；G4 与 G2 并行；G5 需要全部齐备；G6 不阻塞首集用户试玩。不要把小改动拆成多个纯文字 PR 冲散功能方向。

## C. Challenge 最小合同与状态约定

G1 必须采用两个独立类型：Challenge（可判分单题）和 Daily Pack（某一天固定五题、顺序与版本）。至少分清 **编辑状态** 与 **玩家状态**。

编辑状态：draft → fact-reviewed → playtested → approved → retired；证据缺失进入 blocked。事实重审、盲测后才能批准。玩家状态：ready → locked-answer → reveal → resolved → next/completed；刷新从已记录状态恢复。

最小判分不变量：

1. 仅在 ready、题目版本相同且未回答时接受一次 YES/NO；
2. 同题重复事件不得累计分数；
3. 全部题目结果只由同一个 Daily Pack revision 与首次 choice 计算；
4. answer 由审核后题包提供，但不可通过无权限请求玩家状态接口提前取得其他玩家答案；**静态纯前端不提供强反作弊承诺**，答案可从前端资源推断，不做奖品/现金排名；
5. 失效来源和撤题不应把 NO/YES 偷改为另一答案；暂停并显式说明；
6. 离线记录的同一日期必须锁定既有题包版本，新包下载完毕后才能整体切换；
7. 旧问卷记录不删除、不参与成绩，也不能复用相同 localStorage Key。

建议以独立模块/路由实现，例如 game-state.js、game-ui.js、editorial/challenges/，而非放宽 survey-state.js 对评分字段的禁止。正式路径/接口由实现 PR 决定，需提供冷启动、返回和重放行为测试。

## D. 关卡审核的实际清单

每关在内容稿旁记录：

- 玩家目标与购买时刻是什么；YES/NO 对应的两条可执行动作；
- 决定答案的事实是不是在购买前可看到；是否有虚构截屏或把后续法院查明的事实提前展示；
- 真实来源、文内定位、时间、发行地、同款同批次/同服务条款；
- 哪个事实足以让反方选项合理；如存在则不能发布；
- 是「已核验违法」「有风险应谨慎」「不适配该目标」「可证实性价比优势」中的哪一种，而非笼统「骗局」；
- Reveal 第一行是否有反转，第二层能否直接打开官方原文；
- 能否复述一条下次现实可用的识别法；
- 是否允许使用原照片/品牌商标、是否可能误导成官方认定；
- 编辑复核者、盲测结果、有效期与撤题路径。

**已发现的必须先修的问题**：
- corpus/cases/case-consumer-prepaid-retail-deduction.json 把「原价倒扣条款无效」与最高法 2025 典型案例四绑定；原始案例四的主题和事实是经营者举证责任。必须回查司法解释及相应直接判例，明确修订/退役方案。修复前不能入库为标准答案。
- 品牌原产地争议材料在 tasks/consumer-portrait/brand-origin-lead-2026-11-07.md 明确待核查，不得将用户指控当已查实。
- 39 条 CASE、来源数、已核验数按 README 和实际上游库另行确认，不能把全部语料当作可判分关卡库存。
- 两个正向槽位尚未发现可发布商品/服务，**G4 BLOCKED**；先找真实「好物」证据，不通过语言修饰补足。

## E. 前端最小屏幕与状态

- S1：未答单卡。品牌、关卡进度、主要场景视觉、1 个核心问题、NO / YES；键盘可用，屏幕阅读器提供文字等价。
- S2：反馈揭晓。对错状态、短反转、证据展开、下一关。错误不是死路；视觉动画不阻断阅读。
- S3：进度过渡。完成 1～4/5 的轻量进度反馈；不要再堆一张仪表盘。
- S4：结果卡。五格成绩 + 一个已存在的动物伙伴 + 分享挑战。
- S5：返回调查档案与原始来源，再返回同一局。
- S6：加载失败/来源撤题/离线题包过旧/版本变动的恢复状态；不能空白或静默归零。

移动优先：320px 和 390px 布局，无横向滚动；可点击目标不少于 44px；大字号和系统减弱动态设置下可操作；YES/NO 只靠方向或颜色均不够。桌面保留同一体验，不另建复杂编辑控制台。

## F. 最小验证门槛和阶段退出

**G2 开发者自验**：完整 5 关模拟通关、错误 0/5、正确 5/5、正确错误交错、刷新中断、重复双击、返回原文、断网、改版旧存储，全部通过。测试集中在新模块与旧问卷回归，不把每次文本修改升级成全量浏览器回归。

**G4 事实审核**：五关所有标准答案均有独立审核记录、可定位的原始证据；YES 关至少包含真实可对比选项且验证了现时价格/质量/条件；三个来自历史事件的 NO 题不能引入原案没有的事实而冒称已证实；至少一次让不知答案的人盲测表达。缺一个都不算可正式发布。

**G5 真实设备**：至少各一部 iPhone Safari 和 Android Chrome，普通触摸/横竖屏、系统分享返回、VoiceOver/TalkBack 基本完成，资源 404 和离线失败回退。用户访谈建议 6–8 人，测可回答性、难度分布、结果可信度、自然续玩和主动分享动机。真实试玩与真实设备测试尚未执行，不能由自动测试代替。

**公开后才采集**：start / first_choice / reveal_view / next / complete / share_intent / share_success_or_cancel / invite_land / next_day_return，需隐私审查；分母为被实际记录的唯一 session/pack，而不是假定全网用户。定量与访谈交叉验证后再决定是否做无限刷、虚拟预算和复杂角色成长。

## G. Merge 和上线治理

本 PR 可按 **文档方向与任务合同** 评审合并，不代表产品已改造。下一 PR 的技术验收只对新垂直切片，不应为得到绿色检查而破坏旧 self-report 内容验证。之后独立合并首页切换 PR，更新以下文件的运行权威：
- AGENTS.md 当前版与未来版的职责界线；
- docs/product-experience-spec.md 以及 docs/README.md 的 normative 顺序；
- README.md 的首屏定位和版本状态；
- index.html SEO/OG、PWA 资源、release-acceptance；
- 旧问卷数据保存/可访问与变更说明。

只有 **公开完成、5 关完整可用、两个 YES 实证题合格、事实链条可检查、真实设备不卡关、分享入口有效**，才能对外宣布游戏化产品上线。

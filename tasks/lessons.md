# Lessons & Patterns

## 2026-10-25: 题库重构与题目替换经验 (P0–P2 落地)
- **题目替换与归档隔离**：替换线上问卷题目时，严禁物理删除旧题；必须将旧题迁移至 `editorial/retired-questions.json` 并标记 `reviewState: 'retired'`，保留历史问句与原案关联，确保历史答卷不受损且数据库外键约束完整。
- **指纹校验与权威层联动**：案例短读的 `reviewedAgainst` 指纹严格绑定来源（facts/holding/boundary/url等）、规则（text/action）及短读自身 4 要素。新增题目时需在 `corpus/cases` 建立 verified 案例、在 `editorial/game-rules.json` 配置规则，再由 `lessonReviewFingerprint` 严密计算哈希入库，杜绝伪造通过。
- **保持机制与题组数学平衡**：题目替换优先在同一情境组和同一经历机制内等量替换（Q4 储值卡原价倒扣替换儿童乐园年卡闭店），严格维持 2-3-3 情境组分布与 3-2-3 经历机制分布，消除闭店双重同质化，同时保障最低答题门槛（6题）与并列判定模型零扰动。

## 2026-10-25: 整改回查与边界收口经验
- 准入校验双端同步：构建端数据导入（`populateDatabase`）与前端运行时（`validateContent`）防错逻辑必须 100% 对齐，构建端不得放行运行时会拒绝的数据，且构建端必须具备阻止非法映射并完整回滚事务的自动化回归测试。
- 角色设定与答卷证据边界：题目只收集客观遭遇自述，不能在角色文案中逆推消费者的行为习惯（如“习惯按部就班”、“认真对待”）；文案应依托角色本身的插画道具设定（行囊、本子、票据）与实际勾选事实展开。
- 容量与展示预期一致性：当并列结果数量（3个）大于展示卡槽容量（2张卡）时，UI 必须明确告知容量限制（“先选两则对应案例”）并引导其余维度的查阅入口，避免“提取了各维度案例”的误解。

## 2026-10-24: 消费者画像迭代经验
- 阶段依赖规则：必须按 `N01 -> N02/G1 -> N06 -> N07/N08/N09 -> G2 -> N10/N11 -> G3 -> N12/G4` 推进，不能在画像定义未闭合前硬编码推荐规则。
- 自动化与真实测试隔离：模拟浏览器测试（Headless Edge/Playwright）不能代替真机、读屏和真人理解测试，必须在验收记录中严格分栏标注“已验证”与“待执行”。
- 生产闭环与数据保护：短读改写必须触发审核失效（指纹绑定文本），且内容重建绝对不能影响用户已有答卷与待同步队列。
- 阶段门禁必须真实闭环：准备工作（如测试模板、验收矩阵）完成不等于阶段门槛（G3/G4）退出通过。严禁在没有真人受访者原话和真机硬件证据前勾选退出核验。
- 算法模型与覆盖规则自洽：当分类模型（如从题组改为经历机制）升级时，覆盖门槛（minAnsweredPerDimension）、推荐选取逻辑、并列处理与前端输入校验必须全部统一，严禁分类用新机制而覆盖或推荐仍隐式依赖旧分组。
